# Mobile-phone-parser

Скрипт собирает актуальные цены на бюджетные смартфоны в российских магазинах
(market.yandex.ru, ozon.ru, wildberries.ru, dns-shop.ru) через Playwright и headless Chromium.
Список моделей и критерии — из документа «Handoff: подбор смартфона до 15 тыс.».

Репозиторий задуман как общий инструмент сверки цен: после смартфонов он будет использоваться
и для других категорий товаров. Что для этого менять — в разделе «Другие товары».

Искать можно не только по списку моделей: свои ключевые слова вводятся в веб-интерфейсе
(`python parse_prices.py --ui`) или ключом `-q` — см. «Веб-интерфейс».

## Установка

```bash
pip install -r requirements.txt
playwright install chromium
```

В облачной сессии Claude Code Chromium уже стоит: добавляйте `--chromium /opt/pw-browsers/chromium`
или задайте `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. Исходящий HTTPS там идёт через прокси с собственным CA,
и Chromium его не знает (`net::ERR_CERT_AUTHORITY_INVALID`) — один раз добавьте сертификат
в NSS-хранилище браузера:

```bash
apt-get install -y libnss3-tools
certutil -d sql:$HOME/.pki/nssdb -A -t "C,," -n "CCR Agent Proxy CA" -i /root/.ccr/agent-proxy-ca.crt
```

## Веб-интерфейс

Чтобы гонять поиск самому, без консоли и без сессии Claude Code:

```bash
python parse_prices.py --ui          # откроет http://127.0.0.1:8765 в браузере
python parse_prices.py --ui --port 9000
```

В поле «Что искать» — любые ключевые слова: «POCO M7 6/128», «Honor X7d», «чайник электрический 1.7».
Конфигурация «6/128» из запроса сама уходит в фильтр (поля ОЗУ и Память заполнять не обязательно),
кнопки-подсказки подставляют модели из списка. Дальше — галочки магазинов, диапазон цены и фильтры
(только проверенные продавцы, выбросы, модификации Pro/Plus/Max, аксессуары, 5G), в «Ещё настройках» —
окно браузера, системный Chrome, patchright, профиль, прокси, паузы и разбор сохранённого файла.

Две галочки решают, откуда и где искать:

- **«напрямую, мимо VPN и системного прокси»** (включена) — браузер и JSON-запросы идут в обход
  системного прокси, чтобы магазины видели домашний адрес. Через туннель WB отвечает 403,
  Ozon и DNS — заглушкой; в логе это теперь так и написано. Ключ уровня TUN не отменяет,
  в FlClashX российские домены всё равно должны идти DIRECT по правилам.
- **«только категория смартфонов»** (выключена) — свободный запрос ищет по всему магазину.
  С включённой ищется в категории смартфонов (`hid=91491` у Маркета, `category=` у Ozon и DNS);
  именно из-за неё запрос «чайник» раньше выдавал смартфоны Infinix.

В «Ещё настройках» по умолчанию стоит связка, которой Ozon и DNS верят: системный Chrome с patchright,
окно браузера и профиль `.profile`. Без неё (обычный Chromium Playwright) Ozon отвечает «Похоже,
нет соединения» даже с российского адреса, DNS — 403 Qrator. Если Chrome или patchright не
установлены, коллектор сам откатится на Chromium Playwright и скажет об этом в логе.
Во время обхода на странице идёт тот же лог, что в консоли; по концу — таблица с сортировкой
по клику на заголовок, сводка и кнопка «Скачать CSV». Кнопка «Стоп» прекращает обход после
текущего магазина.

Сервер слушает только `127.0.0.1` и запросы с чужим `Host` отклоняет: интерфейс рассчитан
на тот же компьютер, наружу его выставлять не надо. Одновременно идёт один поиск — браузер один.

Устройство: `phone_prices/webui.py` (стандартный `http.server`, новых зависимостей нет) и страница
`phone_prices/ui.html`. Поиск выполняется в отдельном потоке, лог коллектора перехватывается
`collector.set_log_sink`, страница опрашивает `/api/job`.

Свободный поиск доступен и из консоли:

```bash
python parse_prices.py -q "POCO M7 6/128" --sources wb --no-browser
python parse_prices.py -q "чайник 2.0" -s yandex --direct
python parse_prices.py -q "POCO M7" --in-category -s yandex     # искать в категории смартфонов
```

Отличие от моделей из списка: слова запроса ищутся в названии карточки в любом порядке
(«чайник электрический» находит «Чайник Bosch электрический»), числа сравниваются как числа
(«2.0» — это и «2 л», и «2.0 л», но не «1,7 л»), слова из букв и цифр сверяются целиком
(M7 — не M70), модификации Pro/Plus/Max отбрасываются, пока их нет в самом запросе,
и поиск идёт по всему магазину, а не в категории смартфонов. У моделей из `MODELS` правила
прежние: слова названия подряд и своя категория в адресе.

## Запуск

```bash
# Сначала одна модель на одном источнике
python parse_prices.py --models "POCO M7" --sources yandex

# Все модели, все источники (Маркет → Ozon → WB → DNS), с паузами 3–7 с
python parse_prices.py

# Показать окно браузера и сохранять cookies между запусками (помогает против капчи)
python parse_prices.py --headed --profile .profile

# Ozon и DNS с российского IP: настоящий Chrome + patchright. JS-проверка Ozon («Antibot Challenge»)
# в Chromium Playwright заканчивается «Похоже, нет соединения» (инцидент fab_chlg_…): она сверяет
# User-Agent с Client Hints браузера, видит внедрённые скрипты и утечку протокола отладки (CDP).
# С --channel парсер ничего не подменяет, --stealth закрывает утечку CDP.
pip install patchright
python parse_prices.py --sources ozon dns --headed --profile .profile --channel chrome --stealth

# Без браузера: только JSON-источники (сейчас это WB). Playwright не нужен, работает в Termux
python parse_prices.py --no-browser --sources wb

# Разобрать сохранённую страницу магазина (HTML для Маркета/Ozon/DNS, JSON для WB)
python parse_prices.py --from-html dumps/yandex_poco-m7.html --source yandex --model "POCO M7"
```

Результат: `prices.csv` (model, config, shop, price_rub, version, seller, title, url, fetched_at)
и сводка в консоль: по каждой модели минимальная цена Ростест и Global с пометкой
«до 10 тыс.» / «до 15 тыс.» / «вне бюджета».

Сырые страницы и скриншоты капчи складываются в `dumps/` (для каждого адреса модели свой файл:
`yandex_poco-m7.html`, `wb_poco-m7_2.json` — второй адрес). Именно по дампам правятся селекторы:
`--from-html` прогоняет сохранённую страницу через текущий код и печатает все карточки с пометкой
«+» (подошла) / «−» (отсеяна).

При капче или блокировке источник пропускается для модели, скрипт не падает.

## Фильтры

- берутся только 4G-версии (карточки с «5G» в названии отбрасываются);
- только целевая конфигурация 6/128 (для Galaxy A07, Redmi 14C, Infinix Hot 50i — 4/128);
  карточки без указанной конфигурации остаются с пометкой `?`;
- название модели должно встречаться в карточке целиком и подряд: Redmi 15C, Redmi Note 15
  и realme C75 не считаются за Redmi 15 / realme C67; слово Pro / Plus / Neo / Max / Lite сразу
  после названия означает другую модификацию (POCO M7 Pro, Spark 40 Pro Plus) и карточка отсеивается;
- аксессуары (чехлы, стёкла) и карточки дешевле 3000 руб. отбрасываются;
- **только проверенные продавцы** (по умолчанию; `--all-sellers` отключает): карточка проходит,
  если продаёт официальный магазин бренда («Xiaomi Официальный Магазин», DNS), либо у карточки
  не меньше 3 оценок с рейтингом от 4,3; для трансграничных продавцов и перекупов (на Маркете —
  пометка «Из-за рубежа», на WB — «Находки из Китая», «ОАЭшка», «AE Dubai Freezone» и т.п.)
  порог выше — от 4,8. Рейтинг магазина сам по себе не учитывается: у перекупов он тоже 4,9;
- в сводке приоритет у карточек с оценками: цена без оценок берётся, только если оценённых нет,
  и помечается `*`;
- цены выше 2× медианы по модели отбрасываются (`--keep-outliers` отключает).

В `prices.csv` для каждой карточки есть `rating`, `reviews`, `seller_rating`, `cross_border`, `trusted`.
При `--from-html` карточки печатаются с пометкой доверия: `✓` проверенная, `×` из-за рубежа, `?` нет данных.

## Источники: у каждого магазина свои правила

Правила и разметка у магазинов разные, поэтому каждый источник — отдельный модуль в
`phone_prices/sources/` со своими адресами, экстрактором и признаками страниц-заглушек.
Ниже — что выяснено по дампам на 20.09.2026.

### Яндекс Маркет (`yandex`) — работает

- Прямые адреса категорий `/category/smartfony-<slug>` отдают страницу «Что-то пошло не так»
  с HTTP 200; такие страницы распознаются по `data-auto="failure"` и пропускаются.
- Используется поиск `/search?text=<модель>&hid=91491&how=aprice&lr=213`
  (hid 91491 — категория «Смартфоны», `how=aprice` — сортировка по цене, чтобы самые дешёвые
  карточки попали на первый экран). Второй адрес — тот же поиск без hid и с конфигурацией в запросе.
- Карточка: `data-auto="snippet-title"` (название в атрибуте `title`), ссылка `/card/<slug>/<id>`,
  `data-auto="snippet-price-current"` (цена + « ₽»). JSON-LD в выдаче нет. Рейтинг — скрытый текст
  «Рейтинг товара: 4.9 из 5» и «Оценок: (2.8K) · 10K купили»; у трансграничных продавцов в блоке
  доставки написано «Из-за рубежа». Имени продавца в выдаче нет.
- На первом экране 19 карточек, скролл в headless ничего не подгружает; рекламные врезки
  (`data-auto="searchIncut"`, iPhone) отсеиваются по названию модели.
- Регион определяется по IP: с зарубежного адреса часть продавцов показывает трансграничные цены
  по 50–90 тыс., их срезает фильтр выбросов.
- Через curl Маркет сразу уводит на `/showcaptcha`, через headless Chromium с обычным
  User-Agent выдачу отдаёт.

### Wildberries (`wb`) — работает

- Используется тот же JSON-поиск, что и сайт: `search.wb.ru/exactmatch/ru/common/v9/search`,
  запасной — `v5`. На v9 бывает HTTP 429 (лимит запросов), тогда срабатывает v5.
- Ручка отвечает и 403 «Angie» — так было 21.09 у владельца с российского адреса на обоих
  адресах подряд. Запрос теперь уходит с заголовками сайта (`Referer`, `Origin`, `Accept-Language`),
  а третьим адресом идёт сама выдача сайта `wildberries.ru/catalog/0/search.aspx?search=…`:
  страница открывается в браузере, а её собственный XHR к `search.wb.ru` перехватывается
  (`Source.capture`) и разбирается тем же экстрактором. Из облака этот путь не проверить —
  сайт WB отвечает на зарубежный адрес HTTP 498.
- Бренд лежит в отдельном поле `brand`, а `name` часто начинается с категории и без бренда
  («Смартфон M7 8GB+256GB Blue» при brand=POCO); у части продавцов бренд пуст или
  «Нет бренда». Заголовок собирается как бренд + название без слова «Смартфон».
- Конфигурация часто написана через пробел: «6 128ГБ», «6 128». Разбор это понимает.
- Встречаются фейковые карточки вида «16 1024Gb» за 9 тыс. — объём 1024 распознаётся
  и такие карточки отсеиваются как нецелевая конфигурация.
- Цена — `sizes[].price.product` (копейки), продавец — `supplier`, рейтинг товара — `reviewRating`,
  число отзывов — `feedbacks`, рейтинг продавца — `supplierRating`.

### Ozon (`ozon`) — работает с российского IP

- С IP дата-центра (в облачной сессии — зарубежный адрес) на первый же запрос приходит HTTP 403
  и заглушка «Похоже, нет соединения. Выключите VPN…» (инцидент `fab_nmk_…`) — до всякой
  JS-проверки. Коллектор распознаёт её и не тратит время на остальные адреса.
- С российского IP сначала открывается «Antibot Challenge Page», которая проходит сама за несколько
  секунд; коллектор ждёт до 30 с. В Chromium из Playwright проверка заканчивается той же заглушкой,
  но с инцидентом `fab_chlg_…`: антибот сверяет User-Agent с Client Hints браузера, видит внедрённые
  скрипты и утечку протокола отладки (CDP). Рабочий запуск — настоящий Chrome/Edge и patchright:
  `--channel chrome --stealth --headed --profile .profile`; с `--channel` парсер ничего не подменяет.
- Разметка: выдача отрисована сервером в `<div data-widget="tileGridDesktop">`, карточка —
  `<div data-index="N" class="tile-root …">`: ссылка `/product/<slug>-<id>/`, цена
  `<span class="… tsHeadline500Medium …">16 301 ₽</span>`, название `<span class="tsBody500Medium">`,
  рейтинг и отзывы — два `<span class="tsBodyControl300XSmall">` («4.9», «52 отзыва»).
  Классы вида `q3g_21` генерируются и меняются, парсер на них не опирается. Имени продавца
  в плитке нет; бейдж «Бренд проверен» стоит почти у всех и продавца не характеризует.
- Запасной путь — JSON состояния виджетов (`widgetStates`) из XHR-ответов
  `entrypoint-api.bx/page/json/v2` (он же `composer-api.bx`): коллектор перехватывает такие ответы
  (`Source.capture`), сохраняет в `dumps/*_api*.json` и разбирает раньше HTML.
- На первом экране 24 карточки (для Galaxy A17 — 16).

### DNS (`dns`) — работает с российского IP

- С IP дата-центра: HTTP 401 со скриптом `/__qrator/qauth_utm_…js` (антибот Qrator), после
  проверки — HTTP 403 «Доступ к сайту www.dns-shop.ru запрещен». С российского IP страница
  открывается сразу.
- В скриптах страницы лежит словарь формы обратной связи со строкой «Вы не робот» — детектор
  капчи из-за этого срабатывал ложно; теперь он смотрит только на видимый текст, без скриптов.
- Разметка: карточка `<div class="catalog-product …">`, название в атрибуте `title` ссылки
  `catalog-product__name` — там полная спецификация: «6.9" Смартфон POCO M7 128 ГБ черный
  [ядер - 8x(2.8 ГГц), 6 ГБ, 2 SIM, …]», накопитель перед скобкой, ОЗУ внутри; цена
  `<div class="product-buy__price">15 999 ₽</div>`; рейтинг `<a class="catalog-product__rating">
  <b>4.66</b>…521 отзыв</a>`. DNS торгует сам, все карточки считаются официальными (Ростест).

## Результаты прогонов

### Веб-интерфейс у владельца, 21.09.2026 (российский адрес, Chromium Playwright)

Первый прогон интерфейса с запросами «чайник 2.0» и «чайник 1.7», дампы прислал владелец.

- Маркет: с категорией смартфонов в адресе выдал 19 смартфонов Infinix и ни одного чайника;
  после правки (свободный запрос ищет по всему магазину) дамп 18:33 разбирается в 8 чайников,
  все 8 проходят фильтры — 802–882 ₽, BBK и HOME ELEMENT.
- WB: HTTP 403 «Angie» на обе ручки, все четыре запроса. Адрес в дампах Ozon и DNS —
  российский (176.193.132.12), то есть дело не в туннеле.
- Ozon: страница антибота «Похоже, нет соединения», инцидент `fab_chlg_…` — ровно то, что
  магазин отдаёт Chromium Playwright. DNS: 403 Qrator с тем же адресом.
- Вывод: Ozon и DNS требуют настоящий Chrome с patchright, поэтому интерфейс теперь выбирает
  их по умолчанию и откатывается на Chromium Playwright, только если Chrome или patchright нет.

Pova 6 Neo, Hot 50i, realme C67 целевой конфигурации в выдаче нет вовсе.

## Ozon и DNS: как получить данные

Блокировка у обоих по IP, и из облачной сессии Claude Code её не обойти: наружу открыты только
порты 80 и 443, запуск VPN-клиентов (Tailscale и т.п.) внутри сессии запрещён политикой,
а SOCKS/HTTP-прокси на нестандартном порту недостижимы. Рабочих пути два.

**Прислать страницы с телефона (чинит селекторы и даёт цены на момент сохранения).**
В Chrome на Android открыть поиск магазина, в меню включить «Версия для ПК», дождаться
загрузки карточек и нажать «Скачать» — Chrome сохранит `.mhtml` в Downloads. Файл положить
в `dumps/` (закоммитить в репозиторий или прислать в чат) и прогнать:

```bash
python parse_prices.py --from-html dumps/ozon_poco-m7.mhtml --source ozon --model "POCO M7"
```

`.mhtml` читается напрямую. Адреса для сохранения: Ozon —
`https://www.ozon.ru/search/?text=POCO+M7+6/128&category=15502`, DNS —
`https://www.dns-shop.ru/search/?q=POCO+M7+6/128&category=17a8a01d16404e77`.
Достаточно по одной странице с каждого магазина, чтобы проверить и поправить селекторы;
дальше полный прогон делается уже с компьютера.

**Запустить парсер на своём компьютере в России (живой прогон).** Парсер не обращается
к Claude, ему нужен только доступ к магазинам, поэтому VPN для чата с Claude ему не мешает —
но VPN должен быть выключен для самого парсера (split tunneling или запуск без VPN):

```bash
python parse_prices.py --sources ozon dns --headed --profile .profile
git add dumps prices.csv   # dumps/ и prices.csv в .gitignore — добавить через git add -f
```

После этого дампы можно разбирать и править селекторы в облачной сессии.
Флаг `--proxy` (или `PARSER_PROXY`) — для запуска на своём компьютере через резидентный
прокси, из облачной сессии он не поможет.

## Запуск с телефона (Termux)

Wildberries отдаёт JSON, ему браузер не нужен — режим `--no-browser` работает в Termux на Android:

```bash
pkg install python git
git clone https://github.com/Psychophore/Mobile-phone-parser && cd Mobile-phone-parser
python parse_prices.py --no-browser --sources wb
```

Маркет, Ozon и DNS требуют Chromium. В Termux он ставится только внутри proot-дистрибутива
(`pkg install proot-distro && proot-distro install debian && proot-distro login debian`,
затем `apt install chromium python3-pip`, `pip install playwright` и запуск с
`--chromium /usr/bin/chromium`). Playwright не скачивает Chromium под ARM, поэтому нужен именно
пакет из Debian. Работает медленно, на телефоне не проверялось; для Ozon и DNS при этом
используется российский IP телефона, то есть блокировка по адресу снимается.

## Другие товары

Разовую сверку по другой категории можно сделать без правок: свободный запрос в веб-интерфейсе
или `-q` снимает привязку и к списку моделей, и к категории смартфонов в адресе поиска,
а галочки «оставлять аксессуары» и «оставлять 5G» — телефонные фильтры (конфигурация
«ОЗУ/накопитель» не проверяется, если её не задали). Постоянная работа по категории —
свой список моделей и свои адреса:

- `phone_prices/models.py` — список `MODELS`: имя, алиасы (как ещё пишут название), целевая
  конфигурация. Для товаров без конфигурации «ОЗУ/накопитель» поле `config` и правило
  «только целевая конфигурация» в `sources/common.py::accept` нужно заменить своим фильтром
  (например, объём, размер, комплектация). Список суффиксов-модификаций `_VARIANT_SUFFIXES`
  там же.
- `phone_prices/sources/*.py` — адреса поиска по категориям: у Маркета это `hid` (91491 —
  смартфоны), у Ozon `category=15502`, у DNS `category=17a8a01d16404e77`, у WB категории
  в запросе нет. Экстракторы от категории не зависят.
- `phone_prices/offers.py` — разбор конфигурации, версии (Ростест/Global) и цены из названия;
  фильтр аксессуаров `_RE_ACCESSORY` в `sources/common.py`.
- `phone_prices/report.py` — пороги бюджета `BUDGET_LOW` / `BUDGET_HIGH` в `models.py`.

Порядок работы при смене разметки магазина: запустить одну модель на одном источнике,
посмотреть дамп в `dumps/`, поправить селекторы, проверить `--from-html` на дампе, добавить
фрагмент дампа в тест.

## Ограничения

Магазины смотрят, откуда пришёл запрос и чем он сделан. WB на серию запросов с одного адреса
отвечает 403 или 200 с пустой выдачей (21.09 из облака: запрос, отдававший 100 карточек, после
десятка проб стал пустым), а с домашнего российского адреса отдал 403 «Angie» — помогают паузы
и запасной путь через страницу сайта. Ozon и DNS отдают заглушку и зарубежному адресу,
и управляемому Chromium с российского; парсер распознаёт обе и пишет причину в лог.

Все четыре магазина блокируют простой HTTP. Маркет и WB отдают данные headless Chromium
с любого IP, Ozon и DNS — только с российского домашнего адреса, Ozon к тому же только настоящему
Chrome/Edge через patchright (`--channel chrome --stealth`). Из облачных сессий Claude Code
нужна сетевая политика Full и доверенный CA прокси (см. «Установка»).
