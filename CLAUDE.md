# Mobile-phone-parser — контекст для Claude Code

Парсер цен на смартфоны (market.yandex.ru, ozon.ru, wildberries.ru, dns-shop.ru) на Playwright.
Подробности по каждому магазину, разметке, фильтрам и результатам — в README.md, читать его первым.
Репозиторий будет использоваться и для других категорий товаров (раздел «Другие товары» в README).
Цель — коммерческий сервис «что и где купить». План, этапы и решения владельца — `docs/ROADMAP.md`:
сверяться с ним перед новой работой и обновлять раздел «Что уже есть».

## Правила владельца репозитория

- Единственный контрибутор — владелец. Пушить прямо в `main` (fast-forward), PR не нужны.
- Искать только у проверенных продавцов: официальный магазин бренда, либо ≥3 оценок с рейтингом
  ≥4,3; трансграничные продавцы и перекупы допускаются при рейтинге ≥4,8 и ≥3 оценках.
  В сводке приоритет у карточек с оценками. Реализовано в `Offer.trusted` (`phone_prices/offers.py`),
  флаг `--all-sellers` отключает.
- У каждого маркетплейса свои правила и разметка: селекторы править только по дампам этого
  магазина (`dumps/`, `--from-html`), ничего не переносить с одного магазина на другой.
- README обновлять после каждого прогона: что изменилось в разметке, результаты, ограничения.
- Не добавлять в коммиты, README и код имена моделей Claude.

## Как работать

```bash
python -m pytest -q tests                       # тесты парсера (фрагменты реальных дампов) и бота
python parse_prices.py --ui                     # веб-интерфейс владельца: ключевые слова в браузере
python parse_prices.py -q "POCO M7 6/128" -s wb # свободный поиск из консоли
python parse_prices.py --models "POCO M7" --sources yandex     # одна модель, один источник
python parse_prices.py                                          # все модели, все источники
python parse_prices.py --from-html dumps/ozon_poco-m7.html --source ozon --model "POCO M7"  # офлайн по дампу
```

Порядок при смене разметки: одна модель на одном источнике → дамп в `dumps/` → правка селекторов
→ проверка `--from-html` на дампе → фрагмент дампа в `tests/test_offers.py` → README.

## Что где

- `parse_prices.py` — CLI. `phone_prices/collector.py` — обход через Playwright (капча, JS-проверки,
  блокировки по IP, перехват XHR, ожидание селекторов, `--no-browser`, `--channel`, `--stealth`, `--proxy`,
  `--direct` — мимо системного прокси/VPN, чтобы магазины видели домашний адрес, а не выход туннеля).
- `phone_prices/sources/<shop>.py` — адреса, экстрактор и особенности магазина, в докстринге — разметка.
- `phone_prices/models.py` — список моделей и целевых конфигураций (из handoff-документа
  «подбор смартфона до 15 тыс.»), сопоставление названий: `match="phrase"` — слова подряд (модели
  из списка), `match="words"` — все слова в любом порядке (свободный запрос). Там же поля правил
  отбора (`skip_accessories`, `skip_5g`, `min_price`), которые читает `sources/common.py::accept`.
- `phone_prices/query.py` — `build_query`: Model из строки с ключевыми словами (конфигурация «6/128»
  отделяется от слов запроса; `in_category=False` — искать по всему магазину, а не в категории смартфонов:
  «чайник» в `hid=91491` выдаёт смартфоны).
- `phone_prices/webui.py` + `phone_prices/ui.html` — локальный веб-интерфейс (`--ui`): владелец сам
  вбивает ключевые слова, не тратя сессию. Только `127.0.0.1`, зависимостей сверх стандартной
  библиотеки нет, поиск в отдельном потоке, лог через `collector.set_log_sink`.
- `phone_prices/offers.py` — разбор конфигурации, версии (Ростест/Global), цены, правило `trusted`.
- `phone_prices/report.py` — CSV и сводка.

- `bot.py` + пакет `advisor/` — бот-консультант (MVP этапа 2 из ROADMAP): `catalog.py` и
  `data/smartphones.json` — характеристики (имена моделей как в `MODELS`, неизвестное — null, не угадывать),
  `recommend.py` — правила подбора и веса приоритетов, `prices.py` — лучшие цены из CSV в `data/prices/`,
  `dialog.py` — диалог без привязки к мессенджеру, `telegram.py` — Bot API на urllib, `affiliate.py` —
  шаблоны партнёрских ссылок, `events.py` — журнал и `--stats`. Проверка без Telegram: `python bot.py --console`.

## Доступность магазинов

- Из облачной сессии Claude Code (зарубежный IP дата-центра) работают только Маркет и WB.
  Ozon отвечает «Похоже, нет соединения» (инцидент `fab_nmk_…`), DNS — 401 Qrator, затем 403.
  Наружу открыты только порты 80 и 443, VPN-клиенты внутри сессии запрещены, поэтому прокси
  через телефон/компьютер владельца отсюда недостижим — не пытаться.
- Ozon и DNS — с компьютера владельца в России: настоящий Chrome + patchright
  (`--headed --profile .profile --channel chrome --stealth`). Владелец присылает `dumps/`
  архивом или веткой, селекторы правятся здесь офлайн. У владельца FlClashX: российские
  домены идут DIRECT по правилам, Claude Code через туннель.
- Хук `.claude/hooks/session-start.sh` в облаке ставит зависимости, добавляет CA прокси в NSS
  для Chromium и задаёт `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`.

## Незакрытое

- WB отвечает 403 или 200 с пустой выдачей на серию запросов с одного адреса (21.09: из облака сперва
  100 карточек, после десятка проб — пусто; у владельца с российского адреса — 403 «Angie» на обе ручки).
  Запасной путь — страница выдачи сайта с перехватом её XHR — из облака не проверить: сайт WB отдаёт
  зарубежному адресу HTTP 498. Ждёт прогона у владельца.
- Веб-интерфейс по умолчанию берёт системный Chrome + patchright (Ozon и DNS иначе отдают заглушку
  даже с российского адреса); при их отсутствии коллектор откатывается на Chromium Playwright.

- Живой прогон Ozon и DNS с новым кодом (перехват XHR, ожидание цен) владелец ещё не делал:
  экстракторы проверены только на дампах от 21.09.2026.
- `dumps/`, `prices.csv`, `.profile/` в .gitignore; чтобы передать дампы в другую сессию,
  коммитить их через `git add -f` в отдельную ветку.
